# 客户优先选品研究执行手册

本手册用于从真实客户的重复问题出发筛选产品，避免把榜单热度、视频主张或平台估算直接当作需求和利润证明。当前项目仍是 `NO PRODUCT SELECTED`。

## 固定顺序

```text
增长客户群
  -> 可识别渠道
  -> 真实经营者候选
  -> 重复任务与损失
  -> 当前替代方案与最近付费
  -> 持续需求
  -> 多个解决概念
  -> 产品映射
  -> 概念/付费/样品/复购淘汰门
```

Kalodata、FastMoss、Google Trends、Amazon、Etsy、竞品官网和供应平台只能在客户需求之后作为复核证据。

## 一、定义待验证客户群

写成可观察条件，不写想象画像：

```text
地区：<COUNTRY/REGION>
经营/使用行为：<OBSERVABLE_BEHAVIOR>
频率：<REPEAT_FREQUENCY>
销售/活动渠道：<PUBLIC_CHANNEL>
最近活动窗口：<DAYS>
排除条件：<NON_TARGETS>
当前状态：HYPOTHESIS | VALIDATION_COHORT
```

当前第一验证群体是美国每周接单、预售自提、farm stand 或 farmers market 的家庭酸面包微型烘焙经营者。这只是待验证客户群，不代表已选产品。

## 二、建立 100 个候选池

每条记录至少包含：

| 字段 | 规则 |
| --- | --- |
| Candidate ID | 稳定内部编号 |
| Business/Operator Name | 公开名称，不推断法定身份 |
| Country/State/City | 只有公开证据才填 |
| Public URL | 官网、公开商业社媒或市场目录 |
| Business Evidence | 产品/服务、预售、自提或市集证据 |
| Recent Activity | 日期化的近期活动 |
| Repeat Frequency | 每周/每月等；无证据填 UNKNOWN |
| Public Contact Entry | 公开业务联系入口，不抓私人资料 |
| Evidence Date/Source | 每个判断可追溯 |
| Grade | A/B/C/D 与原因 |
| Review Status | 用户审核与是否允许邀请 |

分级建议：

- A：真实经营、近期活跃、群体匹配、频率明确、公开业务入口齐全。
- B：真实且大体匹配，但频率、近期活动或入口缺一项。
- C：弱匹配、内容账号、目录陈旧或关键证据多项缺失。
- D：重复、关闭、非目标、无法区分或明显错误。

未知值保持 `UNKNOWN`，不能从姓名、照片、语言或内容推断年龄、族裔、收入、地点等敏感属性。

## 三、访谈门

发现候选不等于允许联系。用户审核目标、文案、渠道和补偿后，才可发送访谈邀请。

访谈记录围绕事实：

1. 最近一次完成该任务是什么时候？
2. 一周/月发生几次？
3. 哪一步最耗时、最容易损失订单/材料/体验？
4. 当前怎么解决，用了什么工具或产品？
5. 最近 90 天是否为该问题付过钱，付给谁、为何选择？
6. 现有方案哪里仍不够？
7. 若问题消失，哪个可量化结果会改变？

不要在访谈前推销预定产品。意向表达不能替代最近付费和真实行为。

## 四、需求通过门

只有同时满足以下证据才进入解决概念：

```text
[ ] 至少多个独立客户出现同一重复任务
[ ] 频率有可核验或访谈证据
[ ] 问题造成明确时间、材料、订单或体验损失
[ ] 最近 90 天存在真实替代方案付费
[ ] 当前方案仍有一致缺口
[ ] 需求不是由单个视频/评论/榜单构造
```

项目目标为：100 个公开候选、用户审核后 30 个合规邀请、至少 10 个有效回复、至少 8 个完成访谈。这是研究目标，不是已完成数字。

## 五、从问题到多个解决概念

对一个通过的问题至少提出 3 种不同机制的解法：流程/信息、轻量工具、实体产品或组合服务。每个概念记录：

- 解决哪个具体步骤和损失。
- 谁在什么场景使用、频率如何。
- 为什么比现有替代方案更好。
- 是否需要认证、配方、材料、运输或平台合规。
- 最小验证形式和停止条件。
- 供应、单位经济和内容演示风险。

不能先锁定供应商货品，再倒推一个看似合理的客户痛点。

## 六、产品与市场复核

| 证据 | 能说明 | 不能说明 |
| --- | --- | --- |
| Google Trends | 相对关注方向和季节 | 搜索量、销量、利润 |
| Kalodata/FastMoss | 平台模型下的交易/内容代理信号 | 真实结算、留存、全市场需求 |
| 竞品官网 | 产品结构、挂牌、可售状态 | 真实销量、评价真实性、利润 |
| Amazon/Etsy/供应平台 | 供给、挂牌和评论线索 | 客户群需求已成立、供应商合格 |
| 创作者视频 | 方法、主张和内容表现线索 | 作者经营结果或可复制性 |

至少交叉检查客户频率、痛点强度、替代付费、品牌占位、内容适配、供应风险、合规和单位经济。

## 七、逐级验证与停止

```text
问题访谈通过
  -> 多概念点击/等候名单
  -> 透明付费预售或可退订金
  -> 小批样品和使用测试
  -> 首购单位经济
  -> 复购/升级
  -> 才考虑备货和扩量
```

阈值必须在实验前写下，并明确是内部淘汰线，不冒充行业基准。没有用户授权，不联系供应商、不询价、不打样、不备货、不上架、不投广告。

## 故障处理

| 现象 | 处理 |
| --- | --- |
| 搜索结果很多但真实经营证据少 | 降级 B/C，换公开商业目录或官网补证 |
| 平台触发验证/限额 | 停止，不绕过；记录证据缺口与下次配额窗口 |
| 有趋势但无最近付费 | 保持 WATCH，不进入产品验证 |
| 单一店铺数据很强 | 补至少多个独立经营者，不把集中成交外推为市场 |
| 用户说喜欢但不愿付费 | 记录意向与付费分离，回到问题强度或停止 |
| 样品好评但不复购 | 检查使用频率、升级路径和单位经济，不直接扩量 |

## 跨设备恢复

1. 按工作区迁移指南恢复独立站研究文件，知识库只提供方法和入口。
2. 重新读最新状态，保留所有 `UNKNOWN/WATCH`，不要从旧候选自动升级。
3. 核对公开 URL 和最近活动日期；过期证据重新验证。
4. 访谈/供应商/广告动作仍需新的明确授权。
5. 将新结论写入日期化报告，再更新本主题页和项目状态。
