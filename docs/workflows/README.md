# 离线工作流地图

更新日期：2026-10-12

这是知识库的离线交互入口，把资料按“工作目的 → 完整流程 → 对应技能 → 完整原文”组织起来。GitHub 保存文件；交互页面在本机浏览器中运行，不需要服务器、CDN 或 GitHub Pages。

## 直接使用

1. 双击打开 `docs/workflows/index.html`。
2. 首页直接显示可缩放、可搜索的 Archify 总览图；从工作目的进入后，上方直接切换为该目的的十阶段交互流程图。
3. 点击技能卡查看提取出的用途、步骤、依赖和验收信息。
4. 点击“完整原文”打开仓库内 `portable-skills/` 的原始 `SKILL.md`。
5. 需要更大画布时点击“单独打开大图/流程图”；进入“全部技能”时流程图会隐藏，让技能目录保持紧凑。

另一台电脑只需克隆私有仓库并直接打开该 HTML。页面内嵌目录数据，所有运行资源均在文件内；技能是否可执行仍取决于目标电脑的工具、账号、环境变量和依赖。

## 13 类工作目的

| 工作目的 | 解决的问题 |
| --- | --- |
| 客户与市场研究 | 用公开证据验证市场、客户群和需求。 |
| 邮件与合规触达 | 从合格线索形成草稿，经风险和人工授权门后才允许外部动作。 |
| 外贸销售与客户跟进 | 把回复、报价和下一步变成有证据的销售状态。 |
| 选品、核价与商品准备 | 从客户问题和真实成本出发验证商品机会。 |
| 独立站与电商运营 | 在本地候选、预览、质量检查和发布授权之间建立闭环。 |
| 自媒体与内容生产 | 组织选题、脚本、视觉、剪辑和发布准备。 |
| 内容采集、转写与知识蒸馏 | 把来源材料转成可追溯、可检索的知识。 |
| 视觉设计与前端体验 | 从参考和内容目标形成候选界面并做视觉验收。 |
| 软件规划、开发与调试 | 把需求拆成可验证的小步实现和证据。 |
| 测试、审查与质量门 | 用测试、审查和视觉证据阻止未验证结果进入交付。 |
| 部署准备、监控与恢复 | 分层验证服务和环境，不把本地运行误写成生产健康。 |
| 自动化与代理协作 | 明确自动任务的输入、状态、人工审批和恢复。 |
| 知识库维护与跨设备迁移 | 维护来源、哈希、项目状态和跨设备恢复入口。 |

每个目的都有十个固定阶段：目的、触发、输入、底层逻辑、执行、授权、输出、验收、失败处理、状态沉淀。外部发送、发布、部署、购买和账号动作不会因图中出现而自动获得授权。

## 目录与生成

- `index.html`：自包含交互目录。
- `skill-catalog.json`：219 个技能来源实例；同名不同来源分别保留。
- `workflow-catalog.json`：13 个完整流程定义。
- `coverage-report.json`：覆盖率、重复来源、分类和缺失字段报告。
- `sources/`：Archify 输入规格。
- `diagrams/`：总览加 13 张流程图，以及交付和浏览器检查凭证。

重新生成与检查：

```powershell
python scripts/build_workflow_atlas.py . --archify-candidates
python scripts/validate_workflow_atlas.py .
python scripts/validate_vault.py .
```

## 证据与限制

- 当前清单是 219 个来源实例、161 个不同名称，不是 2000 多个独立技能。
- 219 张技能卡当前均为 `WATCH`：原文可以读取，但没有统一包含输入、输出、依赖、验证和失败处理等所有显式章节。缺失字段在详情中标记 `UNVERIFIED`。
- 技能分类采用名称优先的确定性规则。不能可靠判断的实例进入知识维护流程并标记“分类待复核”；分类是导航，不是执行证明。
- 说明文档和源码文件已放入仓库，但并不代表每个技能所需的外部工具、账号或依赖已在另一台电脑安装并验证。
- 14 张 Archify HTML 均有同名 `*.finalize.json`、`*.finalize-summary.json` 和 `*.browser-check.json`。这些凭证记录 9/9 规格检查、交付检查、严格检查和真实浏览器检查。
- 离线目录已在 390×844、1280×720、1440×900 和 2048×1320 下检查，无水平溢出；内嵌总览和邮件流程均在真实浏览器中加载为可交互 SVG，流程切换和独立打开链接指向同一张图，技能视图正确隐藏图表。13 个流程均显示十个阶段。
