## 一、必须长期遵守的要求

### A. 知识库目标与跨设备使用

- **R-001**：知识必须以普通 Markdown 和 Git 文件为主，不绑定某一个 AI 产品。
- **R-002**：私有 GitHub 是跨设备保存层，不需要本机持续开机。
- **R-003**：方案默认不使用付费知识库、数据库、向量库、本地大模型或常驻服务。
- **R-004**：GitHub 仓库必须保持 `Private`，不得启用 GitHub Pages。
- **R-005**：其他电脑必须先登录获授权的 GitHub 账号，再克隆或查看仓库。
- **R-006**：其他 AI 只能在用户授权该私有仓库或上传相关文件后读取知识。
- **R-007**：不假设不同 AI 会自动共享记忆；统一入口是 `AI_CONTEXT.md`。
- **R-008**：知识库保存摘要、规则、证据路径和恢复步骤，不复制所有原始工作区。
- **R-009**：大型 CSV、日志、视频、图片、镜像、压缩包和完整项目代码留在原工作区。
- **R-010**：未经审阅的新内容先进入 `inbox/`，不能直接视为已验证知识。

### B. 每次开始工作的读取顺序

- **R-011**：先读当前仓库或工作区的 `AGENTS.md`。
- **R-012**：再读 `PROFILE.md` 和 `KNOWLEDGE_INDEX.md`，确认长期偏好和主题入口。
- **R-013**：再读 `TASK_STATE.md` 或 `PROJECT_STATE.md`，以持久状态替代长聊天历史。
- **R-014**：项目任务要读对应 `projects/` 页面和原工作区的最新状态文件。
- **R-015**：需要日期化事实时，沿来源卡和证据路径回到原始报告核对。
- **R-016**：先检查已有文件和产物，再生成、修改或重新抓取。
- **R-017**：工作树有现有改动时必须保留，不能擅自清理、覆盖或回滚。
- **R-018**：有意义的进展要写回状态文件，包含完成项、证据、阻塞和下一步。
- **R-019**：线程过长或反复压缩时，应从状态文件开始新任务，而不是继续依赖聊天记忆。
- **R-020**：不同项目的品牌、商店、主题、账号和数据必须保持隔离。

### C. 事实、证据和状态表达

- **R-021**：证据优先，宁可减少数量，也不能补造信息。
- **R-022**：事实、来源主张、AI 推断和未知项必须分开。
- **R-023**：使用 `PASS`、`WATCH`、`FAIL`、`BLOCKED` 或 `UNVERIFIED`，并附证据路径与缺口。
- **R-024**：程序退出码 `0` 不等于业务健康。
- **R-025**：自动化状态 `ACTIVE` 不等于最近一次执行成功。
- **R-026**：草稿、队列、准备、演练、本地构建和未发布主题不等于发送、发布、上线或成交。
- **R-027**：只有最终发送日志中的精确 `Sent` 才能计入真实发送。
- **R-028**：历史快照必须保留日期，使用前重新验证当前状态。
- **R-029**：不能虚构联系人、客户兴趣、价格、产品参数、认证、仓库、公司信息、TDS、质保、评论、销量或分析数据。
- **R-030**：不能虚构权限、平台状态、部署状态、发送、发布、收入或成交。
- **R-031**：遇到 CAPTCHA、429、登录墙、异常空结果或弱验证时停止扩展并标记阻塞。
- **R-032**：报告应简洁，优先给结论、证据路径、缺口和下一步。

### D. 隐私与安全

- **R-033**：密码、验证码、Cookie、会话、API Key、访问令牌和私钥永不进入仓库。
- **R-034**：不读取、复制或展示浏览器配置、指纹浏览器资料、邮箱秘密和账号恢复信息。
- **R-035**：不保存未脱敏的客户个人信息、私人联系方式、支付信息和身份证件。
- **R-036**：`.env`、凭据 JSON、密钥库导出和带认证头的日志不得提交。
- **R-037**：可以记录变量名、非秘密配置位置、错误签名和恢复步骤，但不能记录秘密值。
- **R-038**：Git 会保留历史；发现秘密后必须停止推送、评估影响并受控清理历史和轮换凭据。
- **R-039**：不得给不必要的组织、应用、协作者或 AI 授予仓库权限。
- **R-040**：浏览器和账号操作不得通过读取 Cookie、密码库或配置存储来绕过登录。
- **R-041**：竞品素材默认只作参考，不能直接当作可商用资产。
- **R-042**：第三方视频、评论、图片和文案必须确认拥有、授权或可复用权利。

### E. 外部副作用与授权边界

- **R-043**：公开来源研究、只读检查、本地草稿和本地验证通常可执行。
- **R-044**：真实邮件、私信、评论、WhatsApp 和社交帖子需要当次明确授权。
- **R-045**：表单提交、付款、购买、账号创建或变更需要当次明确授权。

- **R-048**：上传未发布主题不等于发布；切换主主题需要单独授权。
- **R-049**：社交工作是人工审核的执行队列，不是无人监管的批量发送器。

- **R-051**：研究和准备阶段不得用数量暗示已经发送、触达或成交。
- **R-052**：登录墙、验证码、429、安全提示或账号风险信号出现时立即停止。

### F. 安装、磁盘和工具

- **R-053**：安装包、模型、浏览器、Docker 镜像或大型依赖前，先估算下载量和安装后体积。

- **R-055**：大型安装必须先取得用户确认。
- **R-056**：避免把重型工具装到 C:，优先 `D:\codex\.cache`、`D:\codex\tools` 或项目本地环境。
- **R-057**：优先复用现有工具、模型、浏览器和缓存，不重复安装。
- **R-058**：Shopify 开发优先使用已配置的 Shopify 工具和 CLI。
- **R-059**：当前框架文档优先使用已配置的文档工具，不依赖旧记忆猜测 API。
- **R-060**：未经容量估算和确认，不拉取 Docker 镜像或部署推广服务。

- **R-149**：访谈邀请、补偿、供应商联系、询价、打样、备货、上架和广告需要单独授权。
- **R-150**：当前微型烘焙方向只是待验证客户群，不是已选定产品。

### M. PowerShell、文件与交接

- **R-151**：`$env:CODEX_HOME` 可能为空，自动化状态使用已验证的绝对路径。
- **R-152**：当前 PowerShell 不假设支持空值合并语法，使用明确空值判断。
- **R-153**：UTF-8 BOM 或混合换行文件先检查编码和文件头，再做保留式更新。
- **R-154**：文件搜索优先使用 `rg` 或 `rg --files`。
- **R-155**：修改前读取文件，手工编辑优先使用补丁方式。
- **R-156**：不使用破坏性 Git 命令清理用户改动。
- **R-157**：提交前运行知识库校验器；发现疑似秘密时立即停止。
- **R-158**：视觉交付必须有桌面和移动端证据，不能只凭代码或退出码。
- **R-159**：最终交接要说明完成内容、验证结果、阻塞、证据路径和下一步。
- **R-160**：打包前必须得到用户对本审阅稿的明确确认。

### N. 接入与配置细节

- **R-161**：Shopify 接入必须区分主题 CLI、Admin API 和 Storefront API，并说明认证、最小权限、只读验证、未发布上传和正式发布的边界。
- **R-162**：节点配置必须区分 v2rayN 客户端、VPS 传输入口和上游住宅出口，说明字段来源、切换、五层验证和故障处理，同时排除所有真实节点秘密。

### O. 跨设备可执行恢复

- **R-163**：技能清单不等于技能可执行；技能导出默认 dry-run，排除秘密、缓存、日志、数据库、符号链接和 junction，生成 SHA-256 清单，目标端不得覆盖同名文件，插件缓存只能显式选择。
- **R-164**：自动化必须按脱敏规格在目标平台重建，先暂停或 dry-run；时区、工作区、权限和最终证据要重新验证，三个缺少元数据的目录保持 `UNKNOWN`。
- **R-165**：克隆知识库不等于恢复原项目代码和大文件；各工作区应分别使用独立 Private 仓库、Codex task pack 或审阅后的带哈希归档迁移。
- **R-166**：New API 中转恢复必须分层验证 Docker、容器、本地 origin、Cloudflare、公网路由、鉴权和具体模型；秘密与数据库不得进入知识库，持续服务必须有持续在线主机。
- **R-167**：外贸执行必须按发现、发送包、SMTP 探测、预演、明确实发授权、发后邮箱风险复核和监督的顺序执行；下一批被 supervisor 阻塞时不得因脚本可用而发送。
- **R-168**：自媒体账号蒸馏必须使用公开或获授权证据，按导入、转写、构建、覆盖审计、蒸馏和检索执行；标题级证据不得冒充全账号学习，发布与互动仍需授权。
- **R-169**：客户优先选品必须先建立可核验客户池、验证重复问题、损失和最近付费，再做多概念、透明付费、样品与复购实验；平台榜单和趋势不能单独决定产品。
- **R-170**：Private GitHub 跨设备同步必须在提交前后运行测试、知识库校验、差异和秘密检查；其他 AI 只获得必要仓库/文件权限，冲突不得用破坏性命令覆盖。
