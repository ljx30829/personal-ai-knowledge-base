# 内容蒸馏系统

## 证据层级

从弱到强记录，不跨级冒充：

1. 标题、作者、发布时间、时长和公开页面章节。
2. 页面正文、OCR、描述和公开评论摘要。
3. 音频转写、字幕和逐帧联系表。
4. 多条内容的重复模式与反例。
5. 外部第一方数据、实际业务输入输出和后台结果。

只有标题或页面章节时，应标记为页面证据；没有完整转写不能称为逐字学习，没有后台数据不能称为成交验证。

## 标准流程

1. 保存来源卡：平台、URL、内容 ID、作者、时间、采集时间和证据权限。
2. 对媒体做哈希、时长、分辨率和帧率核验；原视频留在原工作区，不进入便携知识库。
3. 优先使用已有字幕；必要时用本地 `whisper.cpp` 转写，并保留 TXT/SRT/JSON。
4. 合并页面、OCR、转写和评论证据，逐条生成“内容、关键点、可复用方法、限制”。
5. 汇总账号知识支柱、反复方法、冲突主张和待验证项，建立本地搜索索引。
6. 把已验证结论提升到 `knowledge/`，原始捕获和未审内容继续留在来源目录或 `inbox/`。

## 本地工具

- 工作区：`C:\Users\26014\Documents\自媒体运营`。
- 模块：`account_knowledge_distiller`，支持 JSON/CSV 导入、抖音导出归一化、媒体捕获、转写合并、质量审计、账号蒸馏和本地搜索。
- 本地转写使用 D: 上的 `whisper.cpp` 和已有模型，避免新的 Torch/Python 大依赖占用 C:。
- 当前规则型蒸馏无需 API、付费服务或常驻电脑。

## 质量门

- 每条结论都要能追溯到视频、页面、转写或独立来源。
- 创作者主张与独立验证分栏记录；金额、销量、利润和工具效果默认不当作已证实事实。
- 浏览器只返回 JavaScript 验证壳时记录 `blocked-js-shell`，不假装抓到了账号视频。
- 当前账号样本曾达到 20/22 转写覆盖；缺媒体 URL 的两条保持页面证据级，不补造转写。
